# 游戏设计文档

整理日期：2026-09-08。设计阶段：概念与系统需求整理。

本文件整合用户已经表达的设定。原始措辞见[逐轮问答原文](interview-record.md)，待定规则及未采纳的建议见[待定事项与建议](decisions-and-open-questions.md)。

文中的来源编号：`I0` 为最初构想；`R1-n` 为第一轮第 n 题回答；`R2-n` 为第二轮第 n 题回答。除明确标注为「倾向」「整理性概括」的内容外，本文件描述用户已确认的方向，不表示开发已经完成。

## 1. 游戏愿景

### 1.1 核心体验

玩家带领一群拥有不同能力、性格、愿望和经历的旅人，在异世界旅行、爬山和探索。

最重要的体验是：**跟同伴一起经历一段旅程，以自己的性格和想法为出发点，判断走哪条路，以及为什么走。**

风景、发现、补给、危险和角色成长共同构成旅程。玩家可以按照自己的喜好组建偏向生活探索、欣赏美景与发掘秘密的团队，也可以组建偏向战斗的团队。

来源：I0、R1-1、R1-5。

### 1.2 平台与呈现

- 单人电脑游戏。
- 平面像素风格；用户给出的感觉参考为《潜水员戴夫》和《Keep Driving》。参考的是用户描述的视觉感觉，不据此推定具体机制或复制现有作品。
- 在大地图上规划路线，到达地点后探索。
- 行走期间会出现突发状况。
- 像素地图上可以看见人物与队伍的图标。
- 地点内部如何操控、具体镜头和空间表现尚未确定。

来源：R1-2、R1-3、R1-12。

### 1.3 世界与国家

旅程跨越异世界的不同国家。世界可以有温暖日常、美丽但危险、神秘古老等不同感受，具体氛围随进入的国家而变化，不为整个游戏统一限定一种情绪。

国家的名称、文化、生态、魔法普及程度和具体地理尚未定义。

来源：R1-4。

## 2. 玩家身份与主线

- 玩家扮演领队／主控。
- 主角是受到保护、没有什么战斗能力的头领，不直接参与战斗或生活型活动的执行。
- 旅人承担具体行动，主角可通过卡牌影响局势。
- 主角能够与各国的重要区域，即旅行地点，建立 connection 或羁绊，以达成主线目的。
- 主线目的、这种连接的世界观原理及建立方式待定。
- 开局会根据主控的身世自动携带一名主旅人。
- 后续旅人可通过雇佣、结识或事件获得。

来源：R1-6、R1-8、R2-4。

## 3. 旅程循环

以下是对既有回答的**整理性概括**，不强制规定每一阶段的执行顺序：

1. 选择卷章，设定主控身世及相关初始内容，获得最初的主旅人。
2. 在城市分配旅人行动，获得情报、金钱、资源和旅行物品。
3. 根据队伍特性、个人喜好、情报及准备情况规划路线。
4. 在像素大地图上移动，处理途中突发状况。
5. 到达地点后探索，参与战斗或生活型活动，并安排露营。
6. 通过练习、事件、学习和升级，获得旅人的成长与塑造。
7. 与重要区域建立羁绊，推进卷章与主线旅程。

是否必须回城、能否随时折返、各阶段消耗多少游戏内时间，尚未确定。

来源：I0、R1-2、R1-8、R1-10、R1-11、R1-12、R2-3。

## 4. 城市：分工、情报与补给

### 4.1 旅人分工

玩家自行分配手中的旅人行动，在尽量获取信息的同时获得资源。

用户认可的城市行动方向包括：

- 与 NPC 交谈、打听消息。
- 利用成员专长接短工或表演赚钱。
- 交易与制作。
- 结交朋友。
- 学习与拜访老师。
- 采购旅行用品。
- 安排成员分头行动。

城市行动的结算时长、次数、费用和能否长期反复执行尚未确定。

来源：I0、R1-10、R1-11。

### 4.2 情报与资源的作用

- 使用团队成员的特性，获得下一张探索地图的信息，例如任务与需要注意的地方。
- 利用团队特性获得金钱及帮助旅行的道具。
- 使用金钱采购旅行所需物品。
- 城镇获得的物品能够在旅途中使用，部分物品会增加可开展的活动。
- 情报以明确地图标记还是需要推理的线索呈现，待定。

来源：I0、R1-11、R2-3。

## 5. 地图旅行与资源管理

### 5.1 路线选择

路线选择是核心玩法。玩家的兴趣、角色性格、团队构成和掌握的信息共同形成出发的理由。

已确认大地图规划、途中事件及地点探索的结构；地图是否固定、是否随机、路线能否回溯以及线索如何揭示路线，尚未确定。

来源：I0、R1-1、R1-2。

### 5.2 旅行管理范围

用户希望包含以下要素：

- 食物。
- 饮水。
- 体力。
- 负重。
- 天气。
- 露营。

用户确认的是要素范围，**没有确认它们的消耗公式、压力强度或失败惩罚**。受伤、死亡、撤退、丢失物资等后果仍待定。

来源：R1-7；失败后果见第二轮未回答问题。

## 6. 旅人：定制、职业与成长

### 6.1 初始定制

玩家可以调整基础数值与基础职业。

用户列举的基础数值有：力量、敏捷、智力、运气、见识、心力等。列表尚未封闭，数值定义、分配预算、上限及作用公式待定。

魔法师转职后可能增加次属性，例如火、水、木、土等。这些是用户示例，不代表已确定完整元素体系。

哪些角色允许调整、在何时调整、招募角色是否保留固定基础，以及能否重新分配，尚未明确。

来源：R1-10、R2-6。

### 6.2 技能与职业

- 旅人高度可定制，并具有持续成长性。
- 武器及武器流派能够给武器技能带来机制，武器技能通常可以成为职业玩法核心。
- 职业、专精和个人经历可以改变旅行能力。
- 用户示例：人类升级习得植物学专精后，可以采摘草药，或者更好地发挥草药效果。
- 是否可以多职业兼修、职业与生活专精是否共存、转职后是否保留旧能力，待定。

来源：I0、R1-6、R1-10。

### 6.3 成长来源

旅人会受到以下过程的成长与塑造：

- 升级。
- 经常从事某件事。
- 经历故事或事件。
- 向老师学习。

基础数值会影响角色发展。成长的具体触发条件、是否由玩家选取、数值增长与特性变化的关系，尚未确定。

来源：I0、R1-10。

### 6.4 性格、弱点与个人目标

性格及特性会影响：

- 能力与状态。
- 对话。
- 可选方案。
- 特殊选项。

用户没有确认「拒绝指令」或「擅自行动」系统，不能把它们写成既定功能。

**用户指定示例：怕高，但想成为登山家。**

- 怕高是长期减益，例如使用绳索登山时容易受伤，或在高处战斗时命中率下降。
- 想成为登山家构成任务。
- 完成克服过程后，减益可以转化为正向增益。

故事、事件和升级能够影响特性及性格。此示例并不表示每一种性格都必须被克服或最终转为增益。

来源：I0、R1-9、R2-5。

## 7. 遭遇与行动准备条

### 7.1 战斗与生活活动

- 战斗型队伍有战斗时的战斗画面。
- 生活型队伍也有对应活动画面。
- 搭建帐篷等生活活动可以用类似「战斗画面」的方式呈现，但使用生活技能。
- 是否所有生活活动都采用完全相同的准备条规则，尚未确定。
- 是否可以几乎不战斗地完成主线，以及不同队伍是否能抵达同一终点，尚未回答。

来源：R1-5、R2-3。

### 7.2 四类准备条

用户称玩法为回合制，并描述了以下准备条。可暂用「准备条制」描述，最终术语待定。

| 类型 | 归属 | 相对节奏 | 满条后行为与作用 |
| --- | --- | --- | --- |
| 普通攻击准备条 | 旅人 | 通常最快 | 默认自动普攻，玩家可以取消 |
| 武器准备条 | 旅人 | 通常比普攻慢 | 提供特效、武器及流派机制，可构成职业核心 |
| 行动准备条 | 旅人 | 尚未给出与其他条的速度关系 | 玩家指定角色技能、使用道具等行动；可提前下令 |
| 主角卡牌条 | 主角 | 尚未给出与其他条的速度关系 | 满条后从手牌选择卡牌，影响局势 |

「四类」不等于每名旅人都有一条主角卡牌条。具体计时单位、初始进度及速度公式待定。

来源：R1-6。

### 7.3 并行与优先级

- 普攻与武器技能可以同时释放。
- 武器技能若涉及蓄力等与时间有关的过程，优先级为：**玩家赋予的动作 > 武器技能 > 普通攻击**。
- 不应把这一优先级泛化为所有行为都必须排队串行。
- 冲突动作是否打断蓄力、是否保留进度、被延后动作如何恢复，待定。
- 武器条满后的默认自动／手动触发规则仍需明确；不能因为普攻默认自动，就推定武器技能同样自动。

来源：R2-2。

### 7.4 预备指令

玩家可以提前给人物下达命令；行动条满时，人物直接执行预备的操作。

预备指令数量、队列长度、能否修改或撤销、目标失效和物品不足时如何处理，待定。

来源：R2-2。

### 7.5 暂停方案：用户倾向，仍在征求意见

用户提出：

- 鼠标 hover 到卡牌或人物时，时间暂停。
- 出牌，或点击人物并完成操作后，结束暂停。

用户同时询问子弹时间是否会更有趣，因此此处保留为**倾向方案，而非最终定案**。

鼠标离开但未操作、菜单切换、指令预备期间、确认后光标仍在原处的行为，以及是否存在手动暂停，尚未确定。助手推荐完整暂停及相关交互细节，但没有收到用户确认，详见[待定事项与建议](decisions-and-open-questions.md)。

来源：R2-1。

## 8. 露营与生活活动

### 8.1 环境条件

暴风雨场景会通知玩家该事件带来的固定减益。不同场景、地区提供不同的可用露营操作。

减益的具体数值、持续时间、是否可消除及与其他状态如何叠加，尚未明确。

来源：R2-3。

### 8.2 人员分配

露营有多种操作，用户明确举例：

- 解决饮食。
- 打猎。
- 周边寻觅。
- 寻找或处理水源相关事务。

玩家需要自行分配人员。活动如何耗时、是否同时结算、成功判定与失败后果，待定。

露营不应被缩减成单独的「搭帐篷」挑战；它包含整个营地生活的安排。

来源：R2-3。

### 8.3 携带物品与休闲

从城镇带来的东西可以在旅行中使用。用户举例包括：

- 打牌消遣用的东西。
- 可以泡澡的东西。

这些物品的存在为生活活动提供内容，但是否增加心情、关系或恢复效果尚未确认，不直接写入数值收益。

来源：R2-3。

## 9. 主角卡牌与羁绊

- 主角通过卡牌影响局势。
- 主角卡牌条完成后，可从手牌中选一张打出。
- 卡牌效果可以包括己方增益、对方减益和直接伤害。
- 可以存在与团队羁绊有关的卡牌。

以下两种「羁绊」需要区分，目前没有确认它们属于同一套系统：

1. 主角与国家重要区域的连接，涉及主线。
2. 与团队有关的羁绊卡牌。

卡牌的叙事来源、获取方式、组牌、抽牌、消耗、手牌数量，以及生活和战斗是否共用牌组，均待定。

来源：R1-6、R1-8、R2-4。

## 10. 卷章与内容组织

- 玩家可以选择卷章。
- 不同卷章包含不同数量的地图。
- 用户举例：卷一可能去 5 个国家，经历 8 个探险地图。
- 上述数量是示例，不是已锁定的制作规模或交付承诺。
- 卷章之间是否继承队伍、卡牌、成长，尚未确定。
- 地图是否必须全部经历、能否跳过国家或选择分支，以及卷章的完成条件，尚未确定。

来源：R1-12。

## 11. 技术与当前实现状态

- 正式引擎尚未由用户确认。
- 助手推荐：Godot + GDScript；像素素材工具考虑 Aseprite。
- 这一推荐基于对自定义 2D RPG 系统和可通过文件、脚本、命令行协作的需求判断。
- 官方文档表明 Godot 有 2D 工具及命令行工作流，Aseprite 有命令行和 Lua 脚本能力。
- 截至最初技术检查，当前会话没有连接好的 Godot 或 Aseprite 专用工具，PATH 与检查过的常见安装目录中未找到对应程序。这不证明机器其他位置没有安装，也不代表已经完成接入。
- 本仓库当前仅记录设计，未创建引擎项目，未安装软件，未实现玩法或素材自动化流程。
