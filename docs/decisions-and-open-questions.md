# 待定事项与助手建议

整理日期：2026-09-19。

本文件与[整合设计文档](game-design.md)配套。第三轮补充引擎、平台、分工、点击探索和失败撤退；W1 补充新星球、返回资格与专长主线；第四轮确认主角本人从地球被放逐、角色选择时的背景信息，以及不参战但参与生活事件的定位。其余问题继续留待需要时讨论。

P1 新增《Cast n Chill》美术偏好，并咨询 roguelike 和暂停复杂度；W2 明确狩奇者家园与地球景观的相似性、NPC 气候情报、灭绝物种发现与回去／留下的结局选择。

M1 新增每张地图的隐藏禁忌与冒犯，可通过探索或其他城镇 NPC 了解。

## 2. 用户明确留待之后回答的主题

第二轮第 7～9 题当时未作答；以下按第三轮补充更新当前状态。

### 2.1 队伍规模、保护主角与失败代价

- MVP 接受小范围提案，建议上限为四名预设旅人选三名出发；完整游戏的队伍上限、是否所有人同时参加遭遇仍待定。
- 已确认失败撤退并丢失部分物品；伤病、恢复、掉落细节与正式游戏是否存在永久死亡仍待定。
- 队伍失去保护主角的能力后会发生什么？

### 2.2 城市时间与资源压力

- 一次分工推进半天、一天，还是其他时长？
- 住宿、食物和雇佣是否需要持续费用？
- 是否允许长期停留、打工、训练，充分准备后再出发？
- 是否存在主线期限？

### 2.3 卷章继承、路线自由与地域羁绊

- 不同卷章是否继承队伍、成长和卡牌？
- 国家与探险地图是否都必须经历，还是可以选路线并错过部分地点？
- 如何与重要区域建立羁绊：帮助当地人、理解故事、试炼，或其他方式？

### 3.1 世界观补充后的故事与规则

- 已解决：主角本人从地球被放逐；主角不参战，但参与露营等生活事件。
- 主角与初始随从在地球是什么关系、各自为何被放逐、是否同次来到新星球，尚未给出。
- 主线类型如何配置背景、职业和放逐原因，是否允许自由组合？选择某类主线是否限制其他活动？均不自行推定。
- 谁认定壮举、如何验证照片或奇兽部位？是否需要提交，谁得到返回资格？
- 与重要区域建立羁绊是壮举条件、额外成长，还是独立主线系统？
- 7 张照片是否必须对应 7 个不同奇观？5 个部位是否来自不同奇兽？暂不自行推定。
- 主角目的之间可否转换或混合，是否需要不同地图？这属于后续设计，不要求 MVP 全部实现。
- 已确认最终可选择回地球或留下；取得资格与选择的具体时点、伙伴能否同行、是否各自决定以及结局后如何游玩，仍未设定。
- 新星球为何与地球相似，是否确为平行时空？当前只记录相似感，不先设定谜底。
- 哪些原本世界已灭绝的物种会出现，以及它们在观察、采集或狩猎中的作用，待定。

### 3.2 禁忌与冒犯的待定细节

- 同一地图的规则是否固定？是否随玩家、远征或地图版本变化？
- 触发前能获得哪些线索、是否需要特定旅人？学到的规则是否跨远征保留？
- 爆炸物禁忌的范围是否只包括物品，还是也包括技能及自动武器效果？用户目前只举了爆炸类物品。
- 调查如何推进，是否必须被看见、能否躲避或交涉、重复爆炸会怎样？
- 被捕回城与普通失败撤退是否有不同的物品损失或恢复规则？
- 居民不满影响哪些关系、服务或后续事件，是否可以补救？
- 神秘花朵消散是本次旅程、限时还是永久？是否影响主线完成，是否有替代途径？
- 禁忌是否也有收益、两类机制能否重叠，以及具体收益与代价如何表达？

## 4. 助手建议：尚未获得用户确认

### 4.1 生活型队伍的完整体验

建议生活型队伍拥有有吸引力的成长和奖励来源，让欣赏风景、发现秘密及帮助伙伴完成愿望成为可持续的玩法。避免最终只有战斗提供最优成长，挤压用户希望保留的队伍风格选择。

这是一项平衡建议，不等同于用户已经确认「完全无战斗通关」。

### 4.2 区分性格与需要克服的状态

建议谨慎、好奇、重感情等性格在不同环境各有作用；怕高等状态可以有个人任务与转变。不要推定所有性格最终都要消除弱点或变成相同的正向配置。

### 4.3 暂停交互的候选方案

助手倾向先用完整暂停，之后与子弹时间进行原型比较，理由是多角色、多准备条与卡牌阅读需要思考时间。

提出但未确认的细节：

- 从人物移向技能或物品菜单时，暂停保持。
- 选择目标等操作完成后再恢复。
- 确认后鼠标仍停在原位置时，避免立即重新触发暂停。
- 增加手动暂停键，便于连续安排多名角色。
- 暂停时准备条、蓄力和持续效果的计时保持一致。

曾按项目约定检索 Lazyweb 的相关交互参考，但结果不足以支撑此类游戏交互比较。因此这些属于助手的设计判断，不是已验证结论。

### 4.4 预备动作的原型简化

建议首个原型每名旅人只预备一个动作，允许修改与撤销。若目标失效或物品不足，保留行动机会并提示重选。

以上均为建议，不能直接当作最终队列规则。

### 4.5 露营与人物故事的候选内容

此前讨论中的以下内容均为助手举例，尚未被用户确认：

- 植物学家通过植被判断水源。
- 社交型旅人从牧羊人处打听避开风暴的小径。
- 在药铺工作与拜访老师之间选择，会分别带来收入、线索或知识。
- 做饭、牌局或被雨困住的露营触发伙伴关系及对话变化。

用户确认的是采药／发挥草药效果、城市分工、露营活动和相关物品等方向，不是上述每条具体事件或收益。

### 4.6 原型范围的演进

助手先后提出过以下相容的原型方向，可作为之后讨论开发范围的起点：

- 一座小镇、一条带岔路的山径、一个营地、几名特性不同的旅人。
- 一次城市准备、一次路线选择、一个生活遭遇和一个战斗遭遇。
- 一次能感知到的旅人成长，用来验证同行与个人目标的价值。

第三轮用户接受了进一步收敛的小范围 MVP 方向，详见[一个月 MVP 计划](mvp-plan.md)。每周安排仍是制作提案，不是已验证交付承诺，不要求第一版完成用户举例的 5 国、8 地图。

### 4.7 技术建议与能力边界

Godot 已由用户选定；GDScript 与 Aseprite 仍为建议。

助手可在安装与权限具备后，通过项目文件、脚本和命令行参与代码、场景、数据、素材处理、运行检查与导出。Aseprite 可考虑通过 CLI 和 Lua 处理图层、帧、调色板及精灵图集导出，再接入 Godot。

这不代表已有专用连接器、已经完全控制编辑器，或素材美术质量可以自动保证。实际运行、画面检查、导出及素材衔接都需要后续验证。

### 4.8 专用 skill 与开发环境

助手建议先在项目中整理轻量开发约定，并跑通创建项目、修改、运行检查和导出的完整流程，再把经过验证的步骤整理为专用 Godot skill。无需先编写完整 Godot 教程或开发专用连接器。

项目约定可覆盖场景与数据位置、技能和事件的表达方式、素材导入、运行检查及导出命令。上述约定和 skill 尚未创建。

建议先在当前 Mac 上开发和试玩，同时配置 macOS 与 Windows 导出。Windows 导出成功不等于 Windows 运行已验证，需在 Windows 实机或可用的 Windows 测试环境上单独验证。

### 4.9 低挫败感的撤退

用户已确认撤退和丢失部分物品。助手建议 MVP 不加入永久死亡，以保留玩家对长期成长旅人的投入。

候选损失边界：优先丢失部分普通补给或本次采集物，保留旅人、成长、已获情报与任务关键物品；避免损失让队伍无法再次出发。具体损失种类、数量、是否让玩家选择及是否有最低补给保障，均未确认。

撤退后保留情报和发现，可让再次出发体现学习与准备，而不只重复相同内容。这是设计建议，尚未变成规则。

### 4.10 将新主线收敛到首段旅程

助手建议 MVP 先采用登山者／探测家方向，只完成一次奇观记录作为长期目标的一步；若采用雪山，可暂拟「前往雪山记录第一处奇观」。雪山、具体奇观和首次拍照目标尚未获得用户确认。

完整游戏的 7 张照片／5 个部位示例不应变成本月的内容清单。首个版本也不必同时完成两套主角主线、复杂摄影操作或返回地球的最终结局。

设计建议：主线目标为队伍提供方向，但为地方故事和伙伴愿望保留绕路理由。奇观的发现应包含情报、准备或路线选择的作用，避免最终只剩连续完成收集计数。这些是候选设计原则，不是用户新增规则。

### 4.11 主角参与方式与首对角色设计

助手建议保持本轮提出的定位：战斗中通过卡牌影响局势，生活事件中亲自参与。暂不增加主角战斗单位、额外普攻或武器条，以便保留旅人的战斗分工，也避免扩大本月范围。是否在正式游戏增加直接参战能力，仍可后续评估。

登山者或狩猎人的专业知识可以通过观察、准备、生活技能或卡牌表现，而不必自动获得直接参战能力；具体例子尚未确认。

生活参与建议先考虑让主角与旅人遵守同样的分工和活动成本，避免主角同时获得免费劳动和无限额外指挥收益。这是候选平衡方向，不是已定的资源或行动条规则。

下一步可先设计一组主角与初始随从：各自地球职业、放逐原因、两人关系，以及此次旅程的不同愿望。MVP 不要求立即完成三类主线的完整人物阵容。

### 4.12 P1 可玩性讨论中的候选方案

以下为助手建议，不代表用户已选择 roguelike 类型或修改了战斗规则：

- 长期保留队伍成长和关系，每次出发变化天气、路况、事件与临时收益。
- 先用手工地图替换少量条件和事件，保留对地理的熟悉感；不要求完全随机生成地图或永久死亡。
- 途中物品、卡牌或食物能形成配合，影响本次行动；具体临时／永久收益边界待定。
- 允许完成阶段目标后主动返程，也可根据状态继续探索。
- 将战斗视为一套可暂停的持续计时，减少必须主动照看的读条；自动或条件触发武器属于候选调整。
- 对比测试悬停暂停与主动暂停加必要时自动暂停；暂不以子弹时间作为首个测试基线。
- 露营可先尝试分配人员后推进时间并结算，无需直接复制所有战斗读条。

### 4.13 W2 的叙事与玩法衔接建议

助手建议把熟悉感分散到旅程中逐步发现：居民一句故乡回忆、一次有用的旅行建议、一个曾只在地球旧资料里见过的生命。这里的具体桥段尚未确定。

NPC 情报可连接「地球经验—当地观察—准备或路线决定」；熟悉经验有价值，但不必保证两个世界完全相同。编写真实地区气候和已灭绝物种细节时应另行查证，清楚区分现实资料与虚构世界设定。

建议让回去与留下都有具体牵挂：地球上的家人与承诺，新世界的伙伴与生活。不要预先将任一选择定为正确结局，也不要假定所有伙伴与主角具有同一愿望。

结合 P1 的远征变化提案，可优先保持聚落、地标及重要人物稳定，变化天气和事件条件，以支持熟悉感和长期关系。此组合仍是建议。

### 4.14 隐藏规则的可玩性建议

以下都是助手建议，未作为用户已确认规则：

- 让触发条件有可发现的线索，探索、NPC 提醒和角色专长都可成为理解规则的途径；避免只能依赖受罚或查攻略来学习。
- 触发后让玩家能理解是哪次行动造成了什么变化。调查启动与最终抓捕分开处理，保留与既有示例一致的因果顺序。
- 冒犯提供有意义的取舍，例如急需的资源与当地关系之间的权衡；具体服务变化、补救和花朵恢复需另定。
- 如果规则会影响自动触发的武器或技能，需要允许玩家提前理解与调整行为，避免自动动作造成不可预期的严重损失。是否扩大到这些行为本身仍待确认。
- 先保持地区的重要规则稳定，让了解一个地方的经验有用；如以后加入远征变化，也应有可辨认的原因和线索。
- 对低挫败感目标，建议主线相关的严重后果存在可预知的风险或恢复／替代途径，不先决定花朵永久消失且主线无法继续。
- 一个地图原型先测试一条禁忌与一条冒犯，占用已有事件预算。调查可先用事件推进，居民反应用一个有限状态记录，无需立刻实现完整军队追踪或复杂声望系统。

候选地图设计记录字段：规则类别、适用地区、触发行为、可发现线索、潜在收益、即时后果、后续状态、持续范围、补救途径。未定字段可留空，不把模板当作新增规则。

## 5. 后续记录方式

后续整理建议继续遵守：用户明确回答后再更新「已确认」；无法确定时保留「待定」；助手举例和原型建议单独归档。原始回答保留在访谈记录中，避免新的概括覆盖用户原意。
